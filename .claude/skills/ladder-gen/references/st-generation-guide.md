# ST 生成ガイド（工程④）

構造化仕様（②）とデバイスマスタ（③）から ST（構造化テキスト, IEC 61131-3）を生成する
ための規約。GX Works3 の ST エディタへ取り込める形を目指す。

## 出力ファイル

`out/<案件名>/03_program.st` にプレーンテキストで出力する。

## 基本構造

```st
(* ============================================================
   案件名: <meta.name>
   自動生成（要レビュー）。ラベル名はデバイスマスタに一致。
   ============================================================ *)

(* --- 1. 安全・非常停止（最上位） --- *)
(* ESTOP は B接点。トリップ時は全出力 OFF *)
IF NOT ESTOP THEN
    MOTOR_FWD := FALSE;
    MOTOR_REV := FALSE;
    (* …全出力を安全側へ… *)
END_IF;

(* --- 2. 状態遷移 --- *)
(* transitions を CASE で表現 *)

(* --- 3. 出力ロジック --- *)
(* 各出力は 1 箇所でのみ代入（二重コイル禁止） *)
```

## 必須ルール（静的チェックで検査される）

1. **二重コイル禁止**: 同一出力ラベルへの代入（`:=`）は ST 全体で 1 箇所のみ。
   条件分岐で複数の値を入れたい場合は、1 つの式・1 つの代入にまとめる。

   ```st
   (* NG: 二重コイル *)
   IF a THEN Y_LAMP := TRUE; END_IF;
   IF b THEN Y_LAMP := FALSE; END_IF;

   (* OK: 1 代入にまとめる *)
   Y_LAMP := (a AND NOT b);
   ```

   例外: `IF/ELSE` の各分岐で同じ変数に代入するのは、実行時に 1 経路のみ通るため可。
   ただしチェッカーの誤検出を避けるため、可能なら単一代入式を優先する。

2. **未定義ラベル禁止**: ST に現れるラベルはすべてデバイスマスタの `label` 列に存在すること。

3. **非常停止の組込み必須**: ESTOP（safety.estop.label）を ST 内で参照していること。

4. **インターロックの実装**: 構造化仕様の interlocks をすべてコードに反映する。
   特に `forbid`（同時 ON 禁止）は、出力式にロック条件を入れて物理的に作れないようにする。

   ```st
   (* MOTOR_FWD AND MOTOR_REV を禁止 *)
   MOTOR_FWD := fwd_cmd AND NOT MOTOR_REV AND NOT ESTOP_TRIP;
   MOTOR_REV := rev_cmd AND NOT MOTOR_FWD AND NOT ESTOP_TRIP;
   ```

## コーディング規約

- 文末は必ず `;`。ブロックは `IF…END_IF;` `CASE…END_CASE;` で閉じる。
- ラベルは大文字 + アンダースコア（マスタと一致）。
- タイマは GX Works3 のタイマ命令/FB に合わせる。中間表現では
  `IF cond THEN T_DRY(IN:=TRUE, PT:=T#5s); END_IF;` のように PT を構造化仕様の
  `preset_ms` から与える（機種の流儀に合わせて後段調整）。
- 自己保持は `M_RUNNING := (set OR M_RUNNING) AND NOT reset;` の形を基本とする。
- コメント `(* … *)` で各ブロックの意図を残す（レビューと保守のため）。

## やってはいけないこと

- デバイスマスタに無いラベルを新規に登場させる。
- 物理アドレス（`Y10` 等）を直接書く（ラベルで書く）。
- 非常停止・インターロックを省略する。
- 同一出力を複数箇所で代入する（二重コイル）。
