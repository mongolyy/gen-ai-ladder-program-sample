# デバイス/ラベル割付（工程③）

ラダー/ST の品質はデバイス割付の精度に強く依存する。AI に物理アドレスを勝手に
決めさせると実機と食い違うため、**ラベル（シンボル名）を正とし、物理アドレスは
デバイスマスタに従う**。

## 原則

1. **AI は物理アドレスを断定しない。** 既存のデバイスマスタがあればそれを入力とし、
   無い項目だけ採番案を提示してユーザーに確認する。
2. **ラベル名は構造化仕様（②）と一致させる。** ラベルがプログラムとマスタを繋ぐ鍵。
3. **マスタが単一の真実。** ST はラベルで書き、物理アドレスはマスタ参照で解決する。

## デバイスマスタの列

`../templates/device-master.template.csv` を参照。CSV 列:

| 列 | 必須 | 説明 |
|----|------|------|
| `label` | ✓ | シンボル名。ST・構造化仕様と一致させる |
| `device` | ✓ | 物理アドレス（X0, Y10, M100, T0, C0, D200 …） |
| `type` | ✓ | BOOL / INT / WORD / REAL など |
| `io` | ✓ | input / output / internal の別 |
| `comment` | | コメント（GX Works3 のデバイスコメントに対応） |

## 三菱 PLC（GX Works3 / MELSEC iQ-R, iQ-F 系）の代表デバイス

| 区分 | デバイス | 用途 |
|------|----------|------|
| 入力 | X | 外部入力（押しボタン・センサ等） |
| 出力 | Y | 外部出力（ランプ・電磁弁・接触器等） |
| 内部リレー | M | 内部ビット（フラグ・状態保持） |
| ラッチリレー | L | 停電保持が必要な内部ビット |
| タイマ | T | タイマ（接点 T、現在値も同名で参照） |
| カウンタ | C | カウンタ |
| データレジスタ | D | ワードデータ（設定値・現在値・演算） |

> 機種・プロジェクト設定によりデバイス範囲は異なる。採番前にユーザーへ機種を確認する。

## 採番のガイド（マスタが無い場合の提案用）

- 入力 `X`、出力 `Y` は実機の端子割付に依存するため、**必ずユーザー確認**。
- 内部リレー `M`、データ `D` は用途別にブロックを分けると保守しやすい
  （例: 状態フラグ M0〜、演算用 M100〜、データ設定 D0〜）。
- タイマ `T` / カウンタ `C` は構造化仕様の timers/counters と 1:1 で対応させる。

## ゲート③ で確認すること

- [ ] 既存資産（他プログラム・他装置）とアドレスが衝突していないか
- [ ] X/Y が実機の端子割付と一致しているか
- [ ] 停電保持が必要な値が L / ラッチ領域 / 保持 D に割り付いているか
- [ ] 構造化仕様の全ラベルがマスタに存在するか（漏れがないか）
